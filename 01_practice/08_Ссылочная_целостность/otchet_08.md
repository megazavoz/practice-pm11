# Отчёт по практической работе № 8
## Тема: Ссылочная целостность в SQLite

**Цель работы:** изучить использование первичных и внешних ключей, а также правила ссылочной целостности в базе данных SQLite.

В ходе работы были созданы таблицы клиентов и заказов. Таблица `client` содержит информацию о клиентах, а таблица `orders` хранит заказы и ссылку на клиента через поле `client_id`. Это позволяет связать одного клиента с несколькими заказами.

Для обеспечения ссылочной целостности был использован внешний ключ. При включённой проверке внешних ключей SQLite не позволяет добавить заказ, если указанного клиента не существует. При попытке добавить заказ с `client_id = 999` появилась ошибка `FOREIGN KEY constraint failed`. Это ожидаемый результат, поскольку клиент с таким идентификатором отсутствует в таблице `client`.

Затем было рассмотрено правило `ON DELETE CASCADE`. При удалении клиента связанные с ним заказы также удаляются автоматически. После этого было проверено правило `ON DELETE RESTRICT`: оно запрещает удалять клиента, если на него ссылаются заказы.

Также была создана таблица товаров с правилом `ON DELETE SET NULL`. При удалении категории товар сохраняется, а значение его поля `category_id` становится `NULL`. Для реализации связи многие-ко-многим была предусмотрена промежуточная таблица с внешними ключами на связанные таблицы.

В отдельной таблице был использован составной первичный ключ из полей `order_id` и `product_id`. Такая комбинация не может повторяться, поэтому повторная вставка той же пары значений вызывает ошибку. Дополнительно была рассмотрена самоссылочная связь: поле `manager_id` ссылается на `id` той же таблицы сотрудников и позволяет хранить структуру подчинения.

В ходе работы также установлено, что при отключённой проверке внешних ключей SQLite может разрешить вставку записи со ссылкой на несуществующего клиента. При использовании `ON DELETE CASCADE` удаление клиента приводит к удалению всех заказов, связанных с ним.

**Вывод:** в ходе практической работы изучены внешние ключи и правила ссылочной целостности в SQLite. Проверены действия `CASCADE`, `RESTRICT` и `SET NULL`, рассмотрены связь многие-ко-многим, составной первичный ключ и самоссылочная связь. Внешние ключи помогают поддерживать согласованность данных между таблицами.
