# Отчёт по работе «Создание таблиц»

## Цель работы

Изучить создание таблиц в SQLite, использование ограничений и установление связей между таблицами.

## Ход работы

В ходе работы были созданы таблицы `category`, `product`, `supplier` и `shipment` для хранения информации о категориях, товарах, поставщиках и поставках.

В таблице `category` были заданы поля `id` и `name`. Поле `id` является первичным ключом, а ограничение `UNIQUE` для `name` не позволяет создавать категории с одинаковыми названиями.

В таблице `product` были добавлены поля для названия, цены, категории и даты создания товара. С помощью внешнего ключа `category_id` товары связаны с таблицей `category`. Для названия установлено ограничение `NOT NULL`, для цены — `CHECK (price > 0)`, а для даты — значение по умолчанию `date('now')`.

В таблицы `category` и `product` были добавлены тестовые записи. Затем была проверена работа ограничений. Попытка добавить товар с ценой 0 не проходит, так как цена должна быть строго больше нуля. При включённой проверке внешних ключей также нельзя указать категорию, которой нет в базе данных.

Далее была создана таблица `supplier` для хранения данных о поставщиках. Для полей `phone` и `email` установлено ограничение `UNIQUE`, предотвращающее повторение номеров телефонов и адресов электронной почты.

Таблица `shipment` предназначена для хранения сведений о поставках. Она связана с таблицами товаров и поставщиков с помощью внешних ключей. Ограничение `CHECK (quantity > 0)` запрещает указывать нулевое или отрицательное количество, а значение `DEFAULT` позволяет автоматически подставлять текущую дату. Также было добавлено составное ограничение `UNIQUE (product_id, supplier_id)`, которое не допускает повторения одной и той же пары товара и поставщика.

Дополнительно была создана таблица с ограничением `CHECK (date >= '2020-01-01')`, проверяющим, чтобы дата была не раньше 1 января 2020 года.

## Результат работы

В результате были изучены основные команды создания таблиц в SQLite, добавления записей, настройки первичных и внешних ключей и применения ограничений `UNIQUE`, `NOT NULL`, `CHECK` и `DEFAULT`. Проверка показала, что ограничения помогают предотвращать добавление некорректных и повторяющихся данных.
